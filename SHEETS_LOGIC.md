# Логика формирования листов «Додаток до аудиту»

**Воркфлоу:** Tech SEO Audit — Screaming Frog (`qirR7k6gtF9FBWaB`)
**Источник данных:** файл `internal_all.xlsx` из Screaming Frog (экспорт Internal → All)

---

## Общие фильтры (Parse XLSX)

Перед обработкой агентами данные проходят предварительную фильтрацию:

| Переменная | Фильтр | Описание |
|---|---|---|
| `all_rows` | Есть колонка `Address` | Все строки из XLSX |
| `pages_html` | `Content Type` содержит `text/html` | Только HTML-страницы |
| `pages_200` | `pages_html` + `Status Code` = `200` | HTML с кодом 200 |
| `pages_indexable` | `pages_200` + `Indexability` = `Indexable` | Индексируемые страницы |

### 2. Canonicals

| | |
|---|---|
| **Колонки** | URL · Canonical (поточний) · Correct canonical |
| **Источник** | Agent 1 ← Parse XLSX (`pages_canonical`) |
| **Фильтр** | Из `pages_html` берутся строки, где колонка `Canonical Link Element 1` **существует** И **не равна** значению колонки `Address` |
| **Логика заполнения** | `URL` = `Address`, `Canonical (поточний)` = `Canonical Link Element 1`, `Correct canonical` = `Address` (всегда = URL страницы) |
| **⚠️ Замечания** | **Колонка "Correct canonical" всегда равна URL страницы.** Это грубое допущение — не учитывает случаи, когда canonical на другой URL является ПРАВИЛЬНЫМ (например: UTM-версия → чистый URL, пагинация → первая страница, дубли → основная страница). SEO-специалисту нужно проверять каждую строку вручную. |

### 4. Структура наявна

| | |
|---|---|
| **Колонки** | Назва сторінки · URL EN · URL UK |
| **Источник** | Agent 1 ← Parse XLSX (`pages_indexable`) |
| **Логика** | Берёт все индексируемые страницы **без** `/uk/` в URL → считает их EN-версиями. Для каждой EN-страницы ищет UK-пару путём замены `https://domain/` → `https://domain/uk/`. Если совпадение найдено — выводит UK URL, если нет — пустая строка. |
| **Название** | Берётся из `Title 1`, если пусто — из `H1-1` |
| **⚠️ Замечания** | Логика поиска UK-пары очень примитивна — просто добавляет `/uk/` к началу пути. Не учитывает: страницы с другим слагом для UK, страницы которые существуют только в UK-версии, hreflang-теги. Пустое значение в колонке URL UK не обязательно означает, что UK-версия отсутствует. |

### 6. Ручні мета-теги

| | |
|---|---|
| **Колонки** | URL · Title · Title LEN · Description · Description LEN |
| **Источник** | Agent 2 ← Parse XLSX (`pages_meta_issues`) |
| **Фильтр** | Из `pages_indexable` берутся страницы, у которых **хотя бы одно** из условий: |
| | • `Title 1` отсутствует |
| | • Длина Title < 30 или > 60 символов |
| | • `Meta Description 1` отсутствует |
| | • Длина Description < 70 или > 160 символов |
| **⚠️ Замечания** | Пороги длины жёстко зашиты: Title 30–60, Description 70–160. Эти значения могут не совпадать с актуальными рекомендациями Google (Title: до 60 пикселей ≈ 50–60 символов, Description: до 155–160). Фильтр `< 30` для Title слишком строг — короткие бренд-титлы будут помечены как проблемные. |

### 7. Декілька Н1

| | |
|---|---|
| **Колонки** | URL · H1-1 · H1-2 · H1-3 |
| **Источник** | Agent 3 ← Parse XLSX (`pages_multi_h1`) |
| **Фильтр** | Из `pages_html` — страницы, где колонка `H1-2` **не пустая** (т.е. есть 2+ заголовков H1) |
| **⚠️ Замечания** | Фильтрует из `pages_html` (все HTML), а не из `pages_indexable`. Значит, сюда попадут и неиндексируемые страницы, и страницы с 4xx/5xx кодами. Также не учитывает, что некоторые CMS (например, WooCommerce) часто имеют множественные H1 by design. |

### 10. 301 сторінки

| | |
|---|---|
| **Колонки** | Address · Status Code · Redirect URL · Redirect Type |
| **Источник** | Agent 4 ← Parse XLSX (`pages_301`) |
| **Фильтр** | Из `all_rows` (ВСЕ строки, не только HTML) — где `Status Code` = `301` |
| **Логика** | `Address` = адрес с 301, `Redirect URL` берётся из `Redirect URL` или `Redirect URI`, `Redirect Type` из одноимённой колонки (по умолчанию `"Permanent"`), `Status Code` всегда `"301"` |
| **⚠️ Замечания** | Включает все ресурсы (CSS, JS, картинки), не только HTML-страницы. Не показывает, какие внутренние ссылки ведут на эти 301 (нет информации о source URL). |

### 11. 404 сторінки

| | |
|---|---|
| **Колонки** | Address · Status Code · Title · Crawl Depth |
| **Источник** | Agent 4 ← Parse XLSX (`pages_404`) |
| **Фильтр** | Из `all_rows` — где `Status Code` = `404` |
| **⚠️ Замечания** | Аналогично 301 — включает все типы ресурсов. Не показывает, откуда пришла ссылка на 404 (нет Inlinks). Crawl Depth помогает понять важность, но отсутствует информация о количестве входящих ссылок на эту страницу. |
